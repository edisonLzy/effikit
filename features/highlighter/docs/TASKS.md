# Highlighter 功能重构任务分解

## 概述

本文档将 Highlighter 功能重构为 React 组件与 Custom Element 结合的架构任务分解为具体的子任务，按照优先级和依赖关系进行组织。

## 任务分解

### 阶段 1：基础架构搭建

#### Task 1.1: 创建 ReactCustomElement 基类
- **文件**: `ui/ReactCustomElement.ts`
- **描述**: 创建通用的 Custom Element 基类，作为 React 组件的容器
- **功能要求**:
  - 实现 Shadow DOM 管理
  - 实现 React 组件挂载/卸载生命周期
  - 实现样式隔离机制
  - 提供抽象方法供子类实现
- **依赖**: 无
- **预估工时**: 4小时
- **状态**: 待开始

#### Task 1.2: 重构 ShadowStyleManager
- **文件**: `shadow-style-manager.ts`
- **描述**: 优化现有的 Shadow DOM 样式管理器，支持 Custom Element
- **功能要求**:
  - 支持 Constructable Stylesheets
  - 提供样式模板管理
  - 优化性能和内存使用
  - 添加样式缓存机制
- **依赖**: 无
- **预估工时**: 3小时
- **状态**: 待开始

#### Task 1.3: 创建事件总线系统
- **文件**: `ui/EventBus.ts`
- **描述**: 实现组件间解耦的事件通信机制
- **功能要求**:
  - 支持自定义事件的发布/订阅
  - 提供类型安全的事件接口
  - 实现事件监听器的自动清理
  - 支持事件命名空间
- **依赖**: 无
- **预估工时**: 2小时
- **状态**: 待开始

### 阶段 2：组件迁移

#### Task 2.1: 创建 HighlightColorPopover Custom Element
- **文件**: `ui/HighlightColorPopoverElement.ts`
- **描述**: 将颜色选择弹窗包装为 Custom Element
- **功能要求**:
  - 继承 ReactCustomElement 基类
  - 实现属性观察和更新机制
  - 处理颜色选择事件
  - 保持原有 React 组件功能
- **依赖**: Task 1.1
- **预估工时**: 3小时
- **状态**: 待开始

#### Task 2.2: 创建 HighlightContentPopover Custom Element
- **文件**: `ui/HighlightContentPopoverElement.ts`
- **描述**: 将内容编辑弹窗包装为 Custom Element
- **功能要求**:
  - 继承 ReactCustomElement 基类
  - 处理复杂的状态管理
  - 实现数据双向绑定
  - 支持多标签页功能
- **依赖**: Task 1.1
- **预估工时**: 4小时
- **状态**: 待开始

#### Task 2.3: 重构 React 组件样式
- **文件**: `ui/HighlightColorPopover.tsx`, `ui/HighlightContentPopover.tsx`
- **描述**: 移除内联样式，使用 Constructable Stylesheets
- **功能要求**:
  - 提取所有内联样式到样式表
  - 确保样式在 Shadow DOM 中正确应用
  - 保持原有视觉效果
  - 优化样式性能
- **依赖**: Task 1.2
- **预估工时**: 2小时
- **状态**: 待开始

### 阶段 3：渲染系统重构

#### Task 3.1: 重构 DomRenderer
- **文件**: `ui/dom-renderer.ts`
- **描述**: 适配 Custom Element 渲染方式
- **功能要求**:
  - 简化 API 接口
  - 移除直接的 Shadow DOM 操作
  - 支持 Custom Element 实例管理
  - 实现组件生命周期管理
- **依赖**: Task 2.1, Task 2.2
- **预估工时**: 3小时
- **状态**: 待开始

#### Task 3.2: 更新 DOM 操作函数
- **文件**: `dom.ts`
- **描述**: 更新高亮渲染相关的 DOM 操作
- **功能要求**:
  - 适配新的 Custom Element 渲染方式
  - 优化高亮元素的创建和销毁
  - 确保与新架构的兼容性
  - 保持现有功能不变
- **依赖**: Task 3.1
- **预估工时**: 2小时
- **状态**: 待开始

#### Task 3.3: 创建高亮内容 Custom Element
- **文件**: `ui/HighlightElement.ts`
- **描述**: 将页面中的高亮标记从注入DOM元素改为使用Custom Element实现
- **功能要求**:
  - 创建 `<effikit-highlight-content>` Custom Element
  - 支持高亮颜色样式属性
  - 实现点击事件处理（显示内容弹窗）
  - 支持高亮文本的包裹和渲染
  - 提供样式隔离和主题支持
  - 兼容现有的高亮数据结构
- **期望效果**: `文本<effikit-highlight-content>被高亮的文本</effikit-highlight-content>啥的啥的`
- **依赖**: Task 1.1, Task 1.2
- **预估工时**: 4小时
- **状态**: 待开始

## 任务统计

- **总任务数**: 20个
- **预估总工时**: 56小时
- **关键路径**: Task 1.1 → Task 2.1/2.2 → Task 3.1 → Task 3.3 → Task 4.1 → Task 4.2 → Task 4.3
- **并行任务**: Task 1.2, Task 1.3 可与 Task 1.1 并行；Task 2.1, Task 2.2 可并行

## 风险评估

### 高风险任务
- **Task 1.1**: ReactCustomElement 基类设计复杂，影响后续所有任务
- **Task 2.2**: HighlightContentPopover 状态管理复杂
- **Task 4.1**: HighlightManager 重构涉及核心业务逻辑

### 缓解措施
- 优先完成基础架构任务
- 为复杂任务预留额外时间
- 实施渐进式迁移策略
- 保持向后兼容性
- 新增的高亮内容Custom Element需要特别注意样式隔离和事件处理

## 里程碑

1. **M1 - 基础架构完成** (Task 1.1-1.3): 第1周
2. **M2 - 组件迁移完成** (Task 2.1-2.3): 第2周
3. **M3 - 渲染系统重构完成** (Task 3.1-3.2): 第3周
4. **M4 - 业务逻辑更新完成** (Task 4.1-4.3): 第4-5周
5. **M5 - 测试和优化完成** (Task 5.1-5.4): 第5-6周
6. **M6 - 文档和发布** (Task 6.1-6.3): 第7周

## 注意事项

1. **向后兼容性**: 确保重构过程中不破坏现有功能
2. **渐进式迁移**: 可以分阶段部署，逐步替换旧组件
3. **性能监控**: 重构后需要监控性能变化
4. **用户体验**: 确保重构不影响用户体验
5. **代码审查**: 每个任务完成后进行代码审查
